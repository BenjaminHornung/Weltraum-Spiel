## Original concrete source findings — both closed below

**P1 — Closing help while still in the start phase hides the route back to New Game.** In `src/factory/ui/factoryShell.ts:121`, the start menu opens the field manual. `closeSurface` at line 151 hides every surface and clears the selected surface; `presentation` at lines 132–142 also hides HUD, utility, keys, dock and resume while phase remains `start`. The Escape handler at line 195 calls the same close path, including directly from the initial start surface. No phase transition occurs to reopen the start menu. A player can therefore dismiss the manual/start menu and lose the visible `Neues Spiel`/`Fortsetzen` controls. The earlier base also allowed start surfaces to close, but retained the global controls; removing that fallback makes the blank UI explicit. Source establishes this state transition; this reviewer did not execute it. Restore the start surface as a UI navigation action when closing in the start phase, without Play, automatic resume or an authority change. A settings surface opened in a future supported lifecycle would have the same close path; today's disabled settings command is not itself evidence of that route being executed.

**P2 — Exported unknown-ID fallbacks allow inherited object keys through.** `src/factory/ui/itemVisuals.ts:13`, lines 49–50 and lines 72–77 use object literals, arbitrary string indexes and `??` fallback. `constructor`, `__proto__` and `toString` have inherited non-null values, so they do not return the documented neutral package symbol or supplied profile label. `factoryItemIcon` then feeds the unexpected value to `forms[shape]` at line 42, producing missing/incorrect constant symbol markup. `cargoPanel.ts:221` has another presentation-only indexed profile icon registry with the same inherited-key behavior. Use own-key lookup or a null-prototype/Map registry and preserve the closed SVG constants. Actual Host/catalog IDs are closed and no such World input was observed: this is a bounded presentation fallback defect, not a security or gameplay-authority claim.

Both findings were sent to Root before the probe. The original final receipts must remain immutable; new fixes need their own source binding and verification evidence.
