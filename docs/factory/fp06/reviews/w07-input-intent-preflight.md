## Minimum bounded contract recommendation

1. **Explicit Factory-only opt-in.** Add a default-disabled input-producer option at the existing construction seam; default Legacy retains its current key sampling/RAF path and existing client behavior. Bootstrap must use the same admitted Factory context as client opt-in. Do not infer Factory mode from key timing or a debug DOM flag. Input owns intent only; native timer and solver retain all position/tick authority.
2. **One shared intent calculation.** In the opt-in producer, accepted movement Down/Up events stage the current normalized yaw-relative axes, current sprint state, and one Space rising edge immediately. Do not calculate a second movement pose or integrate input duration. Existing RAF rendering/camera work remains intact; use the same axis formula to avoid conflicting event/RAF vectors. Ignore unchanged key repeats for transport work. Normal trusted browser keys remain the gameplay evidence path; synthetic unit fixtures must be labeled as such.
3. **At most one event Read in flight, one replaceable pending intent.** Use the existing `Read(input)` transport and `busy` slot; mark a bounded dirty revision when input changes. If idle and admissible, send immediately. If a Read is already in flight, replace the pending level/sprint state with the latest, OR at most one unconsumed jump edge, and drain the dirty latest once after completion. Recheck admission when draining. Clear the staged jump when the actual send captures it; a Read completion must not mark its own already-sent input dirty and recursively stream Reads forever. No event list, timer, polling loop, larger queue, new message kind, or changed backpressure/deadline is justified. Existing `pending.size >= 8` and 20000 ms response deadline remain unchanged.
4. **Producer/client jump ownership must be explicit.** Once an event has staged a Space edge into the client, clear the producer edge so the next RAF cannot stage it again. Repeated Space Down is not a second edge. Ordinary Space Up/zero level intent may preserve one not-yet-sent jump; stop/blur/hidden/Escape/hold/disposal must discard that pending edge. Current generic `setPlayerInput` OR semantics cannot alone distinguish these two cases. Use the existing Pause/Inspect/Play control reset as the cancellation boundary, or a narrowly local explicit cancellation helper; neither requires a Worker IPC addition. Do not silently clear an ordinary Space Up edge or replay a cancelled edge after resume.
5. **Guard producer and dispatch.** Movement requires active pointer lock, undisposed producer, not activating, not hidden/blocked, and a confirmed current client snapshot with native Running/Walking. Suppress dispatch while `mutating`, `bodyPending`, Factory/terrain/structural/moving/neighbor/body-residency/restore work is held or non-idle, or Coverage/Simulation/RecoveryHold/Paused/Disposed is observed. Clear pending motion/edges at these cancellation boundaries rather than flushing stale motion after finalize/resume. On key-up and visibility/focus/pointer-lock loss retain prompt neutral intent/control cancellation; native Pause/Inspect already disables and clears locomotion. Delivery must never issue Play/Resume/Drop automatically or revive movement merely because focus returns.
6. **Guard in-flight Read publication separately from transaction receipts.** At `client.ts:184`, current generic `p.publish` can publish a reply even after a transaction has begun. A Factory event Read started before Prepare may finish after `mutating` becomes true. Prevent that stale/held Read from publishing into authoritative Host snapshot while preserving legitimate transaction publication/finalize/rollback rules. Importantly, blindly using `send(Read, ..., false)` is insufficient: line 185 writes every nonpublishing reply into `heldSnapshot`, which would overwrite the prepared transaction receipt. Track Read publication eligibility locally and keep withheld Read replies out of the transaction-held snapshot slot. No foreign transaction payload or phase should be replaced by coalesced input.
7. **No displacement promise for every zero-duration tap.** Latest-state coalescing can legitimately replace Down with Up while a Read is busy. Even two delivered Worker Read handlers can execute before one native timer step. This opt-in solves RAF-dependent delivery for ordinary short real input; it does not guarantee every 0 ms tap produces movement. Do not add a fake one-tick movement latch, client-side duration integration, injected native tick, speed/position adjustment, or reach increase to make such a test pass. A finite trusted key duration plus actual observed native tick/solver readback is the meaningful browser oracle.
