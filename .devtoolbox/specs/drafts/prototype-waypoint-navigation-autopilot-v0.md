# Draft Spec: prototype-waypoint-navigation-autopilot-v0

Status: draft only. Promote to `.devtoolbox/specs/changes/prototype-waypoint-navigation-autopilot-v0/` before implementation.

## Purpose

Add the first real navigation assistance system for the spaceflight prototype. The current flight model intentionally keeps inertia, RCS, SAS, gimbal, fuel, and realistic drift behavior. That makes manual long-distance and precision travel difficult. The autopilot is therefore a core gameplay enabler, not optional polish.

The first version should navigate between simple visible waypoint objects in space, arrive quickly, and stop near the target with low residual velocity.

## Key Design Decision

Do not simply accelerate for half the distance and brake for the second half. That only works when starting from rest, with symmetric thrust, no lateral velocity, enough fuel, and no controller error.

Use a continuously recomputed burn/brake decision:

```text
closingSpeed = dot(shipVelocity, directionToTarget)
maxDeceleration = availableReverseOrFlipBrakeAcceleration
stoppingDistance = closingSpeed^2 / (2 * maxDeceleration)
```

Switch from acceleration to braking when:

```text
stoppingDistance + safetyMargin >= remainingDistance
```

The calculation must also consider initial velocity and remaining fuel.

## Fuel-Aware Navigation

The autopilot must estimate whether the maneuver is feasible with current fuel.

Minimum first version:

- Read current fuel from the existing fuel/ship stats system.
- Estimate full-throttle burn time available:

```text
availableBurnSeconds = currentFuelKg / fullThrottleFuelKgPerSecond
```

- Estimate required burn time for planned acceleration and braking.
- Warn or enter a `FuelInsufficient` state if fuel is unlikely to be enough.
- Do not fake success by teleporting or ignoring fuel.
- If fuel runs out mid-maneuver, stop commanding main thrust and expose failure/debug state.

Fuel estimation can be conservative and approximate in v0. It does not need full optimal trajectory planning.

## In Scope

- Visible waypoint primitives generated by `PrototypeBootstrap` or a small waypoint manager.
- Select next/previous navigation target.
- Toggle autopilot.
- Autopilot state machine.
- Align to target.
- Accelerate toward target using existing main thruster/fuel behavior.
- Flip-and-burn braking using stopping-distance calculation.
- Arrival tolerance by distance and velocity.
- Lateral velocity correction using RCS if available.
- SAS/RCS-assisted attitude stabilization where possible.
- Debug overlay fields for target, distance, closing speed, lateral speed, stopping distance, fuel estimate, state, ETA, and arrival status.
- Manual abort.

## Out of Scope

- Planets.
- Gravity wells.
- Slingshot planning.
- Orbital mechanics.
- Docking.
- Full map UI.
- Mission routing.
- Multi-leg route planning.
- Obstacles and collision avoidance.
- Fuel-optimal trajectory planner.

## Suggested Controls

- `N`: cycle next navigation target.
- `Shift+N` or `B`: cycle previous navigation target if practical.
- `G`: toggle autopilot, or choose a key that does not conflict with existing controls.
- Manual throttle/attitude input should abort autopilot or switch to manual override mode.
- `M` remains reserved for future orbital/map UI and should not implement a map in this slice.

## Behavior Model

### AlignForBurn

Rotate ship toward the desired burn direction. Use existing attitude/RCS/SAS systems where practical. Avoid direct transform teleport rotation unless there is no viable prototype-safe alternative.

### Accelerate

Apply main throttle while the estimated stopping distance is safely below remaining distance. Continue recomputing because velocity, mass, fuel, and direction can change.

### FlipForBrake

Rotate ship so main thrust opposes the closing velocity/target-relative velocity. This is the prototype equivalent of a flip-and-burn.

### Brake

Use main thrust to reduce target-relative closing speed. If RCS exists, use it for lateral velocity cancellation and final corrections.

### FinalApproach

Reduce throttle and use RCS/SAS to keep position/velocity within tolerance. It is acceptable for v0 to be conservative and slower near target.

### HoldPosition

Keep velocity near zero relative to target. This can be approximate. The first version may simply stop commanding main thrust and use RCS damping if available.

## Acceptance Criteria

- Bootstrap or manager creates at least three visible waypoint targets in space.
- Player can select a waypoint.
- Debug overlay shows selected target name, distance, closing speed, lateral speed, stopping distance, and autopilot state.
- Autopilot can be toggled on and off.
- Autopilot does not teleport the ship or directly set final position.
- Autopilot uses existing Rigidbody/fuel/main-thruster mechanics for acceleration.
- Autopilot computes stopping distance from current velocity and available deceleration.
- Autopilot considers current fuel and fuel consumption in a feasibility check.
- Autopilot can report insufficient fuel rather than pretending the route is possible.
- Starting with non-zero initial velocity changes the braking decision.
- The ship accelerates toward a waypoint, flips/reorients for braking, and reaches the target region.
- Arrival success requires both distance tolerance and velocity tolerance, e.g. within 10 m and below 1 m/s for the first test.
- RCS-assisted lateral correction is used when RCS is present, and missing RCS is documented as reduced final-approach capability.
- Manual override/abort works.
- README documents controls, limitations, fuel behavior, and no-gravity/no-slingshot scope.
- Unity MCP compile/play verification passes.

## Suggested Test Scenarios

1. Start at rest, target 1000 m ahead, enough fuel.
2. Start at rest, target 3000 m ahead, enough fuel.
3. Start with forward velocity, target ahead, verify earlier braking.
4. Start with lateral velocity, verify lateral speed appears and correction is attempted.
5. Set fuel too low, verify `FuelInsufficient` or warning.
6. Toggle autopilot then press manual attitude/throttle, verify abort/override.
