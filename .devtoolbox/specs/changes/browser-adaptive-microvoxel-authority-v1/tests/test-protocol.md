# Test Protocol: Browser Adaptive Microvoxel Authority V1

## Handoff boundary and deterministic evidence

This file describes future implementation-gate verification only. Do not run
builds, tests, dependency installation, browser servers, DevToolbox mutation,
or test-data changes during this artifact handoff. No package, lockfile,
bootstrap, Playwright config, CI group, worker/streaming, renderer/Presentation,
Hestia, or unrelated shared-file change is allowed.

All protocol inputs are literal and deterministic. Evidence contains only
commands, exit statuses, resolved Node major/version, canonical inputs,
outputs, hashes, assertions, and review results. It contains no timestamps,
`generatedAt`, wall-clock values, random values, or claims dependent on runtime
duration. Run the browser proof twice and compare SHA-256 hashes of both
allowed JSON/Markdown evidence files; both runs must be byte-identical.

## Focused unit obligations

Each obligation requires a named focused unit test, literal deterministic
fixture/input, pass/fail result, and reproducible evidence. Renderer observation
or mock success is not authority evidence.

1. **Quantum/levels:** accept only 0.125 m and integer levels 0..4; reject
   invalid values before mutation.
2. **Brick shape:** accept exactly `16^3 = 4096` cells and reject wrong shape,
   channel, length, or level metadata.
3. **Ancestry-closed coordinates:** accept complete valid L0-L4 relationships,
   negative aligned coordinates, and safe `number` bounds; reject alignment,
   half-open-bound, locally-safe/ancestor-unsafe, and non-safe cases without
   clamp/wrap/normalize/`BigInt`.
4. **Parent/child partition:** prove all eight children exactly partition each
   parent with stable half-open bounds and no gap/overlap.
5. **Stable IDs:** reject empty, untrimmed, oversized, and unpaired surrogate
   IDs at construction with the identity error.
6. **Identity/metadata split:** request, worker, cache, telemetry, camera,
   renderer, timing, and completion order do not change authority values.
7. **Closed descriptor:** accept only deeply immutable `constant-v1` with fixed
   schema, identity/version, source revision, and validated finite sample;
   reject function-valued provider/sampler/callback/registry inputs.
8. **Descriptor binding:** descriptor digest changes authority, content,
   provenance, proof, snapshot, and plan bindings.
9. **Base authority:** reject absent, unsupported, malformed, or non-finite
   base data; infer no empty/air/default field.
10. **Immutable ordered journal:** append creates a snapshot; prior records and
    snapshots cannot be mutated; records apply exactly once in order.
11. **Journal rejection:** duplicate/ambiguous/unsupported/conflicting,
    out-of-range, malformed, or non-finite records fail closed.
12. **Canonical serialization:** prove fixed field/type order and stable
    encoding; reject unknown/duplicate/unsupported/non-finite input; exclude
    operational metadata and nondeterminism.
13. **Materialization:** equal key/descriptor/journal inputs produce identical
    bytes independent of request/cache/worker history; A-B-A rematerializes.
14. **Content/provenance hashes:** explicit FNV-1a64 V1 hashes are deterministic;
    changed authoritative inputs cannot reuse unrelated output.
15. **Literal independent vectors:** hard-coded expected UTF-8 bytes and hashes
    cover key, provider, journal, brick, provenance, snapshot projection, proof,
    accepted plan, and rejected plan; expected values are not generated by the
    production helper in assertions.
16. **Context/snapshot:** validate/deep-freeze authority context and inputs;
    prove the projection is canonical and excludes derived proof/digest fields.
17. **Opaque proof:** only the validation constructor issues a locally branded
    proof bound to key, content/provenance, descriptor, journal, revisions,
    planning epoch, and snapshot digest; structural/self-asserted receipts fail.
18. **Planner/fallback:** independently recompute snapshot digest; reject
    wrong-authority/key/provider/journal/revision/epoch/snapshot, forged, stale,
    absent, or malformed proof before selected/fallback coverage; no silent
    downgrade or replan.
19. **Budget/coverage:** required over-budget rejection is typed, deterministic,
    and side-effect empty; optional omission, atomic fallback, selected complete
    half-open gap-free coverage, and exact refinement replacement are proven.
20. **Collapse/eviction:** derived products only are released; descriptor,
    journal, provenance inputs, and identity remain; reload is idempotent and
    byte/hash/provenance-identical.

## Literal pinned vector protocol

Use human-reviewed literal expected canonical UTF-8 bytes and FNV-1a64 V1
hashes for: key; `constant-v1` descriptor; immutable edit journal; materialized
brick content; provenance; non-circular snapshot projection; opaque proof;
accepted plan; and typed rejected plan. The fixture must state which fields are
included/excluded and must not call the production serializer/hash function to
produce its expected value. If a vector changes, stop until an intentional
schema/algorithm reason is recorded and reviewed; unexplained regeneration is
not acceptance.

## Required browser matrix

Run the existing real-browser proof through the normal `/` route, importing the
pure core and exposing read-only evidence. It must machine-prove:

- every L0-L4 cell/brick relationship, parent/child coverage, negative
  alignment, and half-open bound;
- deterministic descriptor variation and A-B-A rematerialization;
- ordered edit replay, immutable journal snapshots, and invalid edit rejection;
- valid proof use, plus stale/cancelled planning epoch and forged/mismatched
  proof isolation;
- required and optional requests, atomic fallback transition, and complete
  selected coverage;
- deterministic budget rejection with empty desired/keep/materialize/evict/
  fallback/coverage side-effect arrays;
- collapse and eviction while retaining descriptor/journal rematerialization
  authority;
- normal `/` behavior with no `window.TestBridge`, browser/page/console/request
  errors, or presentation authority.

Evidence must not claim package/runtime integration, gameplay, rendering truth,
or final surface behavior. Screenshots are optional and only document a visible
proof harness state; they are not visual/product acceptance.
